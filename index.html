    JPMorgan ChaseManhattan Design System team
    Web in use
    
          
    
            
    Checks that grade what coding agents build
    
            
    Agents write UI fast, but they guess: hard-coded colours, hand-rolled buttons, missing labels. I built the checks that catch this in generated code and score it against the design system, so a team can tell whether an agent's output is getting better or just looks busier.
    
            
    
              How it came together
              
    
                
    Problem
    Design system violations reached production because nobody could see them at scale, in code or on screen.
    
                
    What I built
    A linter that flags violations on screen and in code, including in apps that were never built on the system. It won the hackathon it started in, and grew into a graded evaluation of agent output.
    
                
    Now
    Running on web; Android and iOS in progress. Presented up the leadership chain.
    
              
    
            
    
          
    
        
    

        
    
          
    JPMorgan ChaseManhattan Design System team
    Built
    
          
    
            
    A design system that agents can read
    
            
    Component docs are written for people. I rebuilt them for agents: specs in tiers so an agent loads a small core first and pulls the full detail only when it needs it, served through an MCP server so any coding agent can ask the system directly.
    
            
    
              How it came together
              
    
                
    Problem
    Agents given the whole design system run out of context; agents given none of it invent their own.
    
                
    What I built
    An agentic documentation pipeline with tiered specs, and an MCP server over the system's components and tokens. The reference pattern covers 22 edge cases and 52 token bindings, with passing evals.
